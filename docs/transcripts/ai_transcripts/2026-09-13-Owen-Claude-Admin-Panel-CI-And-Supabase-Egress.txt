- Instead, the app gets role a completely different way: `GET /v1/me` re-reads it fresh from
Postgres on every call (`me.service.ts`), and `AdminGate.tsx`/`LandingHeader.tsx` read it from there
via `useMe()`.

That's actually a deliberate choice, documented right in the code — `me.service.ts`'s
`MeProfile.role` comment explicitly says it's "re-read fresh from Postgres... rather than trusted
from the BetterAuth session object directly," specifically because `useSession()` is backed by a
5-minute signed cookie cache (`cookieCache.maxAge`), so a role changed in the DB could take up to 5
minutes to show up if the frontend trusted the session instead.

So: the practical goal (frontend can tell if the signed-in user is admin) is already solved, just
not via this issue's literal mechanism. Worth deciding: close it as "solved differently, on purpose"
with a comment explaining why, or leave it open if you specifically want `useSession()` itself to
carry role for some other reason (e.g. avoiding the extra `/v1/me` round trip). Want me to post that
explanation as a comment on the issue?
