## Swagger/OpenAPI Implementation Instructions

### Context

### Step 2: Bootstrap Swagger in `src/main.ts`

Add after `app.useGlobalFilters(new AllExceptionsFilter())` and before `const port = ...`:

```typescript
import { SwaggerModule, DocumentBuilder } from "@nestjs/swagger";

// ... inside bootstrap(), after app.useGlobalFilters(...)

const swaggerConfig = new DocumentBuilder()
  .setTitle("NBA Analytics API")
  .setDescription(
    "REST API for the NBA Analytics & Optimisation Engine. " +
    "Provides player/team/game data ingested from nba_api, " +
    "Elo-based game predictions, Four Factors analysis, and " +
    "MILP fantasy lineup optimisation."
  )
  .setVersion("1.0")
  .addCookieAuth("better-auth.session_token", {
    type: "apiKey",
    in: "cookie",
    name: "better-auth.session_token",
    description: "BetterAuth session cookie. Required for auth-gated endpoints.",
  })
  .addTag("health", "Service health check")
  .addTag("players", "Player data and statistics (public)")
  .addTag("teams", "Team data (public)")
  .addTag("games", "Game data and predictions (auth required)")
  .addTag("optimizer", "Fantasy lineup optimiser (auth required)")
  .build();

const document = SwaggerModule.createDocument(app, swaggerConfig);
SwaggerModule.setup("api/docs", app, document, {
  swaggerOptions: { persistAuthorization: true },
});
```

```typescript
import { Controller, Get, HttpCode } from "@nestjs/common";

@ApiTags("health")
@Controller("health")
export class HealthController {
  @Get()
  @HttpCode(200)
  @ApiOperation({ summary: "Service health check" })

  }
}
```

hmm ghow does swagger evenwork?

ASSISTANT:
Swagger (now called **OpenAPI**) is basically a contract between your API and anyone who wants to use it. Here's the short version:

## The three pieces

**1. The spec (a JSON/YAML file)**
A machine-readable description of every endpoint: URL, HTTP method, query params, request body shape, response shape, auth requirements, error codes. Think of it as a table of contents for your entire API.

**2. The UI (Swagger UI)**
A web page that reads that spec and renders it as interactive documentation. You can click "Try it out", fill in parameters, hit "Execute", and make real API calls right from the browser — no Postman needed.

**3. The decorators (in your code)**
In NestJS, you slap `@ApiTags("players")`, `@ApiOperation(...)`, `@ApiResponse(...)` etc. onto your controllers. At startup, `@nestjs/swagger` reads all those decorators and **auto-generates** the spec JSON. You never write the spec by hand.

## In your project's case

```
Code (decorators)  →  @nestjs/swagger  →  /api-json (the spec)
                                            ↓
                                     Swagger UI at /api/docs
                                     (interactive documentation page)
```

So when someone visits `https://sportsanalytics-api.onrender.com/api/docs`, they get a page like:

```
┌─ Players ──────────────────────────────────────┐
│ GET /v1/players          List players           │  [Try it out]
│ GET /v1/players/:id      Get player by ID       │  [Try it out]
│ GET /v1/players/compare  Compare 2-4 players    │  [Try it out]
```

Each endpoint is expandable, shows the full request/response schema, and lets you fire real requests. The 🔒 icon appears on auth-gated endpoints, and you can paste your session cookie once to authenticate all of them.

## Why it matters for your rubric

The 15% API criterion says "externally available documented API." Right now your API is externally available (`sportsanalytics-api.onrender.com/health` works), but there's no documentation page for it. Swagger gives you that — a live, interactive, auto-generated docs page that proves the API is documented without any manual upkeep. Every time someone adds a new endpoint with decorators, the docs update themselves.
