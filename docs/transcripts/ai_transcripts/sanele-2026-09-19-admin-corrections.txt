## What a correction is
Player counting stats (points, FG/3P/FT made+attempted, O/D rebounds, assists,
steals, blocks, turnovers) are derived from each game's play-by-play (`GameEvent`
rows). When a play was recorded wrong (wrong player, 2pt vs 3pt, made vs missed,
wrong assist), an admin corrects that one play and the game's stats re-derive
automatically. The project brief requires corrections to "leave a history behind
them": who changed what, from what, to what, when, and why.

## Backend: bugs and gaps to fix
1. Double-counting bug: recomputeDerivedStats only updates players who still act
   in the game's events AFTER the correction. If you move a player's ONLY play
   to someone else, the old player isn't recomputed and keeps the points. The
   test "moves derived stats to the corrected player..." passes by coincidence,
   because its seeded stat rows start at 0. Fix it (at least recompute the
   corrected event's previous playerId), and make that test seed non-zero stats
   so it would have caught this. Don't regress the PR #181 behaviour: players
   who never act in a game's events keep their stats. That matters because
   older games hold only period-marker events, and replay must not zero them.
   Note the side effect: a player with no events drops out of the credit
   roster (see 3); decide how to handle that and explain it.
2. No input validation. Today, bad input either causes a 500 (non-integer
   period, unknown teamId FK) or silently corrupts stats: an unknown eventType
   drops the points, a playerId not in the game is accepted (GameEvent.playerId
   has no FK), and value 5 on a 2pt counts 5. Validate the RESULTING event
   (existing row merged with the patch) and return 400 with a clear message:
   - eventType must be in the platform vocabulary (mirror KNOWN_ACTION_TYPES in
     apps/ingestion/event_validation.py)
   - period is an integer from 1 to 10
   - clock is well-formed
   - playerId is null or a player with a PlayerGameStat row for this game
   - teamId is null or the game's home/away team, and matches the player's team
   - success is only set for 2pt/3pt/freethrow
   - value is consistent with type and success
   First inspect real ingested rows so valid existing plays aren't rejected.
3. Assists/blocks/steals are not fields. They're a "(Name N AST|BLK|STL)"
   suffix on the event's description, resolved by folded surname (optionally
   first-initial-prefixed, e.g. "L. James") against players who act in the
   game. An assist must come from the shooter's team; a block or steal from the
   other team. Assists attach to made shots, blocks to missed shots, steals to
   turnovers. Admins need a structured "Assisted by / Blocked by / Stolen by"
   choice (including "none") that rewrites the suffix for them. Prefer doing
   the rewrite server-side, where the roster and folding logic already live.
   Confirm with resolveSecondaryPlayer that the rewritten credit resolves to
   the intended player, and reject it if not. The N in the suffix is cosmetic
   to the derivation.
4. correctEvent reads the "before" row outside the transaction. Move it inside.
5. Stored clocks are ISO durations like "PT11M30.00S" (some older test rows use
   "11:30"; check real data). The UI shows and edits mm:ss and converts back.
