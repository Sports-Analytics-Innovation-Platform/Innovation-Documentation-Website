**What happened:** it wasn't your PR fix breaking anything — the coverage job runs `Run API
coverage` then `Run Web coverage` as sequential steps in one job. Before, the API step always failed
first (the Prisma disconnect bug), so the job never got far enough to actually exercise the Web
coverage step in CI. Once that got fixed and merged, the job ran `Run Web coverage` for real for
possibly the first time in a while, exposing a second, unrelated, pre-existing bug: several web spec
files never mock `@/lib/authClient`, so the real `better-auth` client's background session-refresh
timer and cross-tab `BroadcastChannel` get created for real during those tests — and under CI's
concurrent, resource-constrained execution, that timer can fire *after* the test file's jsdom
environment is torn down, throwing `window is not defined` from inside `better-auth` itself,
attributed to whatever file happened to be running at that moment (hence `ComparePage.spec.tsx`
looking involved when it probably wasn't the actual source).

**Fix:** one file, `apps/web/src/test/setup.ts` — a global mock for `better-auth/react`'s
`createAuthClient` so no unit test ever instantiates the real client (no real timers, no real
BroadcastChannel). `authClient.spec.ts`, which legitimately needs to test the real wrapper logic,
keeps working because its own local mock override takes precedence for that file. Verified: full
local suite (56 files / 449 tests) still passes, `authClient.spec.ts` included, plus clean typecheck
and lint.

Couldn't reproduce the race locally (ran the full suite twice, no failure) — expected, since it's
timing-dependent on CI's specific load, so real confirmation needs a green CI run same as the other
fix. This is also independent of #151 and #152 — merge it on its own whenever ready.
